# Image Editor P0：PSD 技术验证

研究日期：2026-10-06（Asia/Shanghai）。

**结论：可继续开发受限的像素图层编辑原型；不能承诺 Photoshop 全兼容或任意 PSD 无损写回。**
P0 自动化研究、已发现缺陷与 Photoshop 实机验收分别记录。正式验收状态仍为
`pending-photoshop`，不因自动测试通过而关闭。

- 独立的 `@haiyue/image-editor` workspace，固定 `ag-psd@31.0.2`；没有 UI 或 AI 依赖。
- 15 份外部 PSD/PSB 样本及上游参考结构，附固定 commit、SHA-256、字节数和 MIT 许可。

- 每例诊断报告、实验写回文件及 [Photoshop 人工验收步骤](photoshop-acceptance.md)。

本次没有运行 Photoshop，来源元数据不算 Photoshop 实机验证。

本次独立检查：10 份外部样本的图层、蒙版像素和基础结构精确一致，1 份调整层样本写回后

## 关键发现与影响

### 1. 文档资源静默丢失

11 份可读取样本中，10 份 raw codec 写回会丢失图像资源，包含 ICC（1039）及其他块。
`ag-psd@31.0.2` 的资源读取器跳过部分未实现资源，也不总产生警告；仅打开
`logMissingFeatures` 不足以证明保真。

已加入原始资源 ID 扫描、ICC 诊断和导出资源丢失拦截。P0 只检测资源缺失，没有实现任意
未知块无损透传，也未验证每个已知资源块内容不变。因此不提供“只改一个图层也能保留
全部 Photoshop 数据”的保证。

### 2. 半透明合成缓存量化

5 份真实样本的合成缓存 RGB 在读写后改变，但其图层/蒙版像素仍完全一致。
固定版本 codec 会在合成图编码/解码过程中加入/去除白色 matte，8 位量化会放大
低 alpha 区域的直通 RGB 误差。

这些样本的直通 RGB 最大差异为 31—63/255；alpha 未变化，预乘 RGB 最大差异约
1.31/255。报告同时记录三种指标，不能只展示其中较小的数值，也不能称为逐像素无损。
生产导出需要确定合成缓存编码策略、透明边缘容差并用 Photoshop 实测。
独立解码器对这些缓存的直通 RGB 比较最大差异可达 64/255；不同解码器的取整差异也记录
在报告中，不据此上调或隐藏合成质量指标。

### 3. 极窄透明合成图编码异常

1×1、1×32、2×1 的受控透明样本出现合成 alpha 损坏。P0 已加入导出后 alpha 自检，
遇到异常直接拒绝。没有修改第三方依赖，也没有通过扩大画布掩盖问题；需要在生产
导出前定位和修复编码缓冲区问题或替换该路径。

### 4. 同库通过不等于跨软件通过

调整图层样本原件能被 psd-tools 读取，但 raw codec 写回后，psd-tools@1.10.9 报
`Invalid signature`。该项作为不兼容结果保留，不能将自动化执行完成解释为所有样本
跨软件通过。仍需定位到具体调整块，确认是写入格式问题还是解码器差异，并由 Photoshop
复核。

### 5. 真实合成图缺失必须单列

`pass-through` 样本的 `hasRealMergedData=false`。文件中有字节不代表存在有效参考图；
该样本合成对比标为 unavailable，不计入精确重绘通过数。

## 技术选择

暂时保留 ag-psd 作为受限编解码后端，通过适配层隔离。它可以支撑基础像素编辑研究，
但 P3 之前需要补齐资源保留、透明合成编码和独立兼容性问题。

内部文档、图层像素和合成器独立维护；采用直通 RGBA 字节数组，避免 Canvas 自动预乘
造成额外损失。P0 CPU 合成器只做正确性参考，不据此锁定生产 CPU/GPU 后端。

报告中的小文件耗时是本地单次诊断，包含结构预检开销，不是 2K/4K、多图层、Worker 或
GPU 性能承诺。大文档预算、分块存储、压力测试和内存释放需要后续基准。
