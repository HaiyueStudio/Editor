# P3：PSD 导入、编辑与兼容副本导出

> 后续 P5 已扩展简单像素蒙版和混合模式，并增加文字／形状栅格化、调整合并导出。当前边界见 [P5 兼容矩阵](p5-content-and-masks.md)，下文保留 P3 阶段记录。

P3 接通 PSD → 分层编辑 → PSD 兼容副本 → 重开流程。支持范围为 RGB、8 位、PSD v1，
复用 P1/P2 像素文档与工具。**这不是任意 Photoshop 文档的无损写回实现；Photoshop 实机验收仍待完成。**

## 用户流程

- “打开”或拖放 `.psd` 后，在可取消的 Worker 中解析；显示文件名、合并图预览与兼容报告。
- 支持的基础图层可选择“分层打开”；含不支持内容时禁用此按钮。
- 用户明确选择“打开合并图副本”后，才从原 PSD 的有效合成图创建单张栅格图层。
  文件声明没有真实合成图时禁用回退，不能把占位图当作原件内容。
- CMYK、16/32 位、PSB、额外 Alpha/专色通道、损坏文件和超预算文档明确拒绝。
  取消或失败不会改变现有文档。每次只处理一项 PSD 任务，任务限时两分钟并可终止。
- “导出 PSD”显示范围说明，后台编码当前快照、自检，再下载 `文档名.edited.psd`。
  不覆写源 PSD；任务期间的新编辑仍留在当前工程，完成提示说明快照差异。
- `.hyimage` 与自动恢复同时保存保留的 PSD 图像资源；导出 PSD 不把工程标记为已保存。

## 兼容范围

| 项目 | P3 行为 |
| --- | --- |
| 像素层、Unicode 名称 | 分层导入；像素逐字节导出自检，包括 alpha=0 的隐藏 RGB |
| 图层顺序、位置、显隐 | 保留；组偏移转换为 PSD 子层的文档坐标 |
| 普通、正片叠底、滤色 | 支持；CPU 参考合成器生成 PSD 合成缓存 |
| 隔离图层组 | 保留树结构、合成模式与不透明度 |
| 锁定 | Photoshop 部分保护标志统一为本编辑器整层锁定，导出为透明度/位置/合成保护 |
| 不透明度 | PSD 使用 255 级，导出按最近整数归一化；兼容提示中明确告知 |
| 穿透组、蒙版、剪贴、Blend If | 分层准入拒绝，可在有效原合成图上明确回退 |
| 文字、矢量、智能对象、调整层、效果 | 不保留可编辑语义；仅显式合并图回退，不将缓存像素伪装成完整支持 |
| ICC | 原资源字节保留；当前显示/绘图未实施 ICC 颜色转换，会提醒颜色可能与 Photoshop 不同 |
| 图像资源 | 保留非派生资源原始块；旧缩略图、图层索引等按明确清单重建或移除 |
| 应用专用数据 | 图层标签、链接、图案预设等不保留；未知附加信息块会阻止分层准入 |

图像资源的原始字节保留不表示其中尺寸、历史、XMP 等语义已同步更新，也不表示完整文件无损。
工程新增可选 `psdOrigin` 字段，兼容现有版本 1 `.hyimage`；资源最多 16 MiB，恢复时重新校验。

## 对 P0 阻塞项的处理

1. **资源丢失**：独立扫描 PSD 图像资源块，将源 ICC 等未由 codec 保留的内容带入内部工程。
   导出重建区段长度，并对保留资源进行字节往返验证；对会失效的派生记录采用显式清单。
2. **窄幅透明合成损坏**：图层使用 ZIP 编码，最终合成区段由适配层写入 raw planar 数据，
   避开固定版本 codec 的 RLE 临时缓冲区问题。没有扩大画布或更改用户图层来掩盖缺陷。
3. **透明缓存量化**：PSD 合成透明缓存采用白色 matte 约定，低 alpha 直通 RGB 仍有量化误差。
   同时记录直通与预乘误差，要求 alpha 精确、预乘 RGB 最大差异 ≤1/255，图层 RGBA 精确。
4. **调整层跨解码失败**：不写入调整层结构，明确拒绝分层导入；显式回退使用原件合成图。
   原 P0 不兼容证据保留，不能视为修复了任意调整层写回。
5. **截断与未知数据**：在解压前检查图层/蒙版尺寸和总量；独立验证 raw/RLE 合成长度、
   每行解码像素数及附加信息块，防止库忽略坏数据后继续开放编辑。

区段与通道排列依据 [Adobe PSD 文件规范](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/)。
固定 `ag-psd@31.0.2` 仅通过其公共 API 使用，没有修改第三方源码。

## 验证

- 62 项产品单元测试，覆盖 P0/P1/P2 回归，以及 PSD 图层/资源往返、未知块、损坏输入、
  透明窄幅图、空白文档和 Worker 取消/重试。
- 7 个导出用例由独立 `psd-tools@1.10.9` 打开；层级、名称、位置、不透明度及层像素检查通过。
  合成 alpha 精确；独立强制重绘的 alpha/预乘 RGB 容差为 2/255，全部通过。
- 独立检查使用 32 位计算中间值避免 8/16 位溢出，且把解码器 warning 视为失败。
  输出同时写入文档 Unicode 名称；无头解码器对极短文件的全局掩码读取边界已纳入窄幅样本验证。
- 浏览器验证兼容报告/取消、真实 PSD 编辑撤销、Worker 导出重开、文字合并回退、CMYK 拒绝、
  缺失合成图拒绝、工程恢复后资源导出，以及断网后的 Worker/codec 加载与导出。
- P1 和 P2 浏览器工作流继续回归。应用描述符、资源预算、类型、仓库边界/API 检查通过。

证据保存于 `../evidence/p3/`，临时 PSD 和报告位于 `../artifacts/p3/`，绑定 revision、dirty、
源码指纹、运行器及样本哈希。浏览器使用本机已安装的 Chromium Headless Shell，未操作日常浏览器数据。
Web/PWA 与 Electron renderer 构建得到验证；不代表原生安装包、全部浏览器或大图性能验收。

复现：

```sh
npm test -w ./imageEditor
PSD_P3_PYTHON=/path/to/python-with-psd-tools npm run p3 -w ./imageEditor
npm run test:browser:p3 -w ./imageEditor
npm run test:browser:p2 -w ./imageEditor
npm run test:browser -w ./imageEditor
npm run app:check -w ./imageEditor
```

`CHROME_PATH` 可指定已有浏览器；独立 Python 环境沿用 `scripts/requirements-p0.txt`。
未提供独立解码器时标为 `pending-independent`，不会写成验收通过。
