# 名片与透视样机 PSD

针对桌面 `psd/3d-preview-mockup.psd` 和 `psd/bc2.psd` 补充了分层导入能力。原文件只读，不作为仓库测试素材提交。

## 支持范围

- 正向 X／Y 独立缩放的点文字、自定义原点／行距、自动行距、千分之一 em 字距和小数字号。导入使用原像素缓存；修改文字时应用保留的缩放、基线及字距，PSD 导出写回这些参数。字体缺失时仍可能使用本机替代字体。
- 四角构成凸四边形的嵌入式像素智能对象。保存原 PSD 源和透视四角；替换源图或回写智能源时，通过逆单应矩阵及预乘透明度双线性取样重新生成缓存。退化、自交四边形和非恒等网格变形仍拒绝。
- 智能对象与独立矢量蒙版可以共存。读取 PSD 的矢量派生蒙版缓存来保持外观，保留路径、标志及图层相对坐标。移动图层时原生路径随图层平移；修改蒙版像素会转换为像素蒙版并删除旧矢量描述，撤销恢复原路径。尚未新增矢量蒙版节点的可视化编辑器。
- 正常穿透分组、停用效果描述、效果面板展开状态，以及解析器已支持的 `lfxs`、`lyvr`、`lnkE`、`Txt2` 等字段。未知附加块和不支持的活动效果仍明确报告，避免静默丢弃。
- 小型 RGB8 文档遇到上述原生特性也可使用保留档案的按需导入路径，不再只有超过内存预算的大 PSD 才能进入该路径。

蒙版路径和放置记录遵循 [Adobe PSD 格式规范](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/) 的字段结构；未修改的文字、放置、效果和嵌入源尽量复用原描述。导出合成图由本编辑器重建，测试通过不代表 Photoshop 实机认证。带蒙版的交互式自由变换仍沿用现有显式限制；替换智能源会保持透视和蒙版。

## 验证

```sh
npm test -w @haiyue/image-editor
npm run build:app -w @haiyue/image-editor
npm run check:boundaries
CHROME_PATH=/path/to/chrome node imageEditor/test/mockup-psd-browser.mjs /absolute/path/to/psd
```

合成测试验证透视恒等映射、浮点数值、透明边界、非法四边形、原生往返、源图替换、撤销、蒙版转换与工程保存。外部文件的浏览器测试验证分层入口、异步画布、智能源读取／替换、四个文字层的编辑、Worker 导出重开，并检查原文件 SHA-256 不变。证据和截图保存于忽略的 `artifacts/mockup-psd/`。

## 本次验收结果

286 项单元测试、构建、应用产物校验和仓库边界检查通过。最终浏览器报告绑定构建 `d7f012675a8935dd`：两个原文件均可分层导入；样机为 10 层／组（含 4 个带透视与矢量蒙版的智能对象），名片为 5 层（含 4 个文字层）。源图替换、四个文字层的修改与撤销、未修改原生描述及嵌入源的往返、修改后的 PSD 重开均通过，原文件哈希不变。

原像素缓存合成与文件内合并图相比，样机 RGBA 通道平均绝对差约 0.0031、最大差 2；名片平均约 0.0595、最大差 20（通道范围 0–255，局部文字边缘存在差异）。另外回归了此前 114 层的桌面 `sample.psd` 完整闭环。

浏览器验收还定位并修复了自动恢复迁移像素到磁盘期间的绘制缺页竞争：纯读取在补齐缺页后重试，不重放编辑操作。
