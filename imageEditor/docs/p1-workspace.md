# P1：Image Editor 工作区

## 范围

完成“新建文档 → 导入图片 → 管理图层 → 保存恢复副本 → 重新打开”的工作流。
实现位于独立 `imageEditor` workspace，复用共享 Editor Platform、Shell 和 App Kit。
本阶段没有画笔、选区、裁剪、变形、文字排版或正式 PSD 编辑导入/导出；它们分别属于
P2/P3。P0 PSD 兼容性结论及待 Photoshop 实机验收状态保持不变。

## 已实现

| 模块 | 行为 |
| --- | --- |
| 工作区 | 顶部文件操作、工具栏、多文档标签、中央画布、导航器、图层与属性面板 |
| 文档 | 透明或白色画布、新建、重命名、切换、带未保存提示的关闭；最多 8 个同时打开 |
| 图片 | PNG/JPEG 打开为文档，或按原尺寸居中导入为图层；损坏/超限文件不修改文档 |
| 图层 | 空白图层、图层组、同级排序、复制、删除、重命名、显隐、锁定、组内添加 |
| 合成 | 正常、正片叠底、滤色；组隔离合成；图层不透明度与像素坐标 |
| 浏览 | 滚轮围绕指针缩放、拖动平移、适合窗口、实际像素、每个文档独立视图 |
| 历史 | 每个文档独立撤销/重做；像素所有权隔离；回到保存点可恢复干净状态 |
| 工程 | 版本 1 `.hyimage`，包含完整 RGBA 图层字节、树结构、属性、尺寸和选择 |
| 恢复 | 原子 IndexedDB 会话替换、串行写入、刷新恢复、跨窗口写锁、失败提示 |
| 发行基础 | 独立产品描述符、Web/PWA assembly、字节一致的 Electron renderer、静态资源预算 |

`ImageDocument` 是唯一可变业务入口，每次命令先验证新快照，再进入共享 History Service。
画布与缩略图均从文档像素派生；复制图层拥有独立像素缓冲区。视图、输入框和解析器不直接
修改历史快照。恢复加载先校验整个会话，避免损坏的第二份文档导致第一份被部分载入。

保存使用浏览器文件选择器（若可用）；取消选择或写入失败时保留原未保存状态。
下载回退会发起 `.hyimage` 下载，并完成可用的浏览器恢复写入后更新保存状态。
自动恢复与用户工程文件是不同的持久化目标，自动恢复不会清除未保存标记。

## 当前边界

- 最大边长 8192，单张图片/画布最多 16,777,216 像素；单文档最多 128 图层、
  16 层组嵌套、128 MiB 原始像素。PNG/JPEG 文件最多 32 MiB，在浏览器解码前检查尺寸。
- 这些是 P1 的输入边界，不是整个进程的内存上限。参考 Canvas 2D 渲染、JSON/base64
  工程编码和自动恢复仍在主线程，大图流畅度、分块存储、Worker 和压力测试属于后续工作。
- 图片由浏览器解码成 RGBA；工程准确保存得到的像素，尚不保留原 PNG/JPEG 元数据或
  进行 Photoshop ICC 保真承诺。图层组采用隔离合成，未提供穿透模式。
- 历史预算为每文档 256 MiB、最多 100 个命令；新历史会按预算淘汰旧命令，重开工程
  会恢复当前状态，不恢复整条撤销历史。
- 本地恢复随浏览器数据清理而消失；更换端口属于不同 origin。外部 `.hyimage` 文件可以
  在其他浏览器重新打开。产品没有上传文件或访问第三方服务。
- 原生 Electron 安装包运行、签名及跨平台发行尚未验收；P1 只验证共享 renderer assembly。

后续 P2 可在当前文档/命令边界上添加绘图、选区和变换；PSD 的受限导入/导出通过
独立适配层接入，不能绕过 P0 已发现的资源丢失与透明合成风险。
