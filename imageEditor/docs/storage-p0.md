# 存储 P0：磁盘页回收与流式工程

本轮只处理前次评估的两项 P0，不包含 PSD/TIFF 解码提速或 GPU 合成迁移。

## 磁盘页生命周期

磁盘页仍以 SHA-256 内容地址去重，不改变原有像素精度。页引用注册为弱根，随实际不可变快照存活：当前文档、撤销／重做、共享源、显示缓存及未完成任务持有的页均受保护，不需要把像素加载到内存。关闭文档清除其内容引用；历史淘汰、取消任务、关闭暂存或失效缓存后，不再引用的页会进入回收范围。

回收与页 I/O 串行，保护正在租用的工作集；同一 IndexedDB 事务读取最新恢复清单，再扫描并删除不被引用的 `page:` 数据。恢复清单仍引用的页不会删除，恢复自身的 `chunk:` 清理由既有事务负责。失败事务整体回滚，不影响后续读写。

每个浏览器执行环境持有共享 Web Lock。回收仅在能取得独占锁时进行；其他窗口或 Worker 仍存活时返回 `busy`，不会依据心跳超时删除暂停窗口的数据。浏览器缺少 Web Locks 时返回 `unavailable` 并保留页。当前策略较保守，多窗口长期同时使用会推迟物理回收。

自动回收每分钟尝试一次；`image.storage.trim` 可主动执行，并返回 `collection.status`、删除页数、删除字节数与保留页数。只有 JS 引用被垃圾回收后，弱根才会消失，因此关闭句柄不保证立即释放物理空间。导入／导出暂存会主动检查 30 分钟空闲期限，释放句柄根，不再依赖下一次 API 调用触发过期。

## 二进制工程容器

`.hyimage` 新增 v20 二进制容器：64 字节头部、带 SHA-256 的 JSON 目录、去重后的原始页数据、完成标记。每个页按内容哈希校验，目录声明总长度、缓冲数量及页数量；不接受截断、多余、重复、缺失或哈希错误的页。文件处理完成并验证文档后才发布新文档。

- 文件最大 2 GiB；磁盘像素页不再计入原来便携 JSON 的 128 MiB 总页限制。
- 页数据以至多 256 KiB 分段读写，不收集完整文件，也不转 Base64；目录上限 16 MiB。
- 文档既有内存工作集、几何、层数和原生元数据预算不变；非分页内存缓冲仍限制 128 MiB。
- 包含像素、蒙版、智能源、PSD 原生档案、ICC、画板及专色等现有工程数据；旧 JSON 工程 v1–19 和便携 JSON 包继续可读。
- UI 对含磁盘页的工程使用二进制保存，普通小工程保留 JSON 保存兼容。打开按内容识别格式，扩展名均为 `.hyimage`。
- 支持直接文件写入的浏览器使用写入流，成功后关闭提交，失败或取消时 abort。无该接口时沿用最多 512 MiB 的 Blob 下载回退，超过时使用分段 API。UI 提供工程任务进度和取消按钮。

## API

保持 125 个 Image 命令，没有引入新的传输层：

- `image.export.prepare({format:'project'})` → `export.read` → `export.close` 输出二进制工程。读取单段最多 4 MiB，支持偏移重试，报告保存进度。
- `image.import.begin({format:'project',size,name})` → `import.write` → `import.finish` → `import.close` 支持二进制或旧 JSON 工程，报告打开进度。
- `image.document.open({format:'project',resourceId,name})` 自动识别两种格式。
- `image.document.export({format:'project'})` 保留既有 JSON 资源兼容及 128 MiB 预算；更大工程使用分段输出。工程始终保留 ICC，不接受省略配置。

保存使用开始时的文档快照，保存期间的新编辑保持未保存状态。导入损坏或取消不会创建文档、覆盖当前文档或改变撤销历史；产生的临时页由生命周期回收处理。
