# 富文本 PSD 兼容

针对桌面 `psd/rich-text.psd` 补齐导入、内容编辑及原生 PSD 往返。外部素材只读，不提交到仓库。

## 支持的内容

- 横排点文字及矩形段落文字框；保留原点、框范围、四系数仿射变换（缩放、旋转、斜切）、字号、行距、字距、段落缩进和段前／段后间距。
- UTF-16 样式区间中的字体名称、小数字号、粗体、斜体、下划线和 RGB 颜色。文字编辑对话框支持插入／删除后的区间迁移、选中文字应用样式、原生文字框宽度修改；公共 `image.content.update` 使用同一内容模型。
- 闭合路径的内侧描边和 Points 单位宽度（根据描边分辨率换算）。路径编辑保留描边对齐；修改形状后删除旧的矢量派生像素蒙版，避免旧轮廓裁切新路径。撤销恢复原蒙版和内容。
- 小型嵌入 PSB 智能源。先验证尺寸、图层数和解码预算，再转换到内部可编辑 PSD；保留未修改的原始 PSB 字节与批注。允许相对原点或 warp bounds 偏移的恒等 4×4 网格，实际曲面形变仍拒绝。

导入继续使用 PSD 自带的图层像素缓存，编辑某个内容层后才重新生成该层缓存。未改动的文字、矢量、放置描述优先复用原记录，编码器可能将隐含默认值规范化（例如省略的黑色填充写成显式黑色）。修改文字后重建该层文字数据，并去除陈旧的全局文本缓存。PSB 源修改后写回普通 PSD，并更新对应资源类型。

内容模型新增 `TextContent.layout.transform`（4 个矩阵系数）、`box`（left/top/right/bottom）及段落参数；`PathContent.strokeAlignment` 支持 `center` / `inside`。工程保存、恢复、撤销和 API 校验均保留这些字段。

## 范围与限制

- 重新排版使用浏览器字体和排版。缺失字体、字偶距、断词、抗锯齿或 Photoshop 排版规则可能导致外观变化；并非 Photoshop 实机认证。
- 图层名称里的 `<TCC_3>`、`<TVA_center>`、`<TOS_FitToBox>` 等是素材命名标签，不视为标准 PSD 排版指令。没有根据名称实现自动分栏、垂直居中、自动缩字或绕任意对象排版。
- 实际沿曲线路径文字、竖排、多段落独立样式和非恒等文字／智能对象网格变形仍报告未支持。
- 此次只支持现有预算内的嵌入 PSB，不开放任意顶层大 PSB。智能源仍受 32 MiB 文件、64 MiB 解码、128 层及禁止嵌套智能对象的限制。
- 新建的无原生布局富文本／自动换行内容沿用原来的 PSD 栅格化提示。

## 验证

```sh
npm test -w @haiyue/image-editor
npm run build:app -w @haiyue/image-editor
npm run check:boundaries
CHROME_PATH=/path/to/chrome node imageEditor/test/rich-text-psd-browser.mjs /absolute/path/to/rich-text.psd
CHROME_PATH=/path/to/chrome node imageEditor/test/mockup-psd-browser.mjs /absolute/path/to/psd
```

合成测试不依赖外部素材，覆盖富文本和仿射参数的原生往返、内侧小数描边、矢量派生蒙版清理／撤销、带批注的嵌入 PSB、源编辑以及非法布局／真实形变的拒绝。

真实文件浏览器验收包含 15 层／组：8 个文字层、2 个路径层、1 个智能对象、3 个分组和背景。逐个文字层执行修改、Worker 导出、重开和撤销；另验收文字对话框的范围格式与框宽度、路径编辑、智能源读取／回写。未编辑的嵌入源字节和原文件 SHA-256 保持不变。报告及截图位于忽略的 `artifacts/rich-text-psd/`。

原像素缓存重新合成后，与原文件合并预览的 RGBA 通道平均绝对差为 0.5968、最大差为 40（通道范围 0–255）；约 3.76% 的像素至少一个通道相差超过 1，包含文字抗锯齿边缘。例：坐标 (241,32) 的黑色文字缓存 alpha=170，覆盖白色图层后为 85，而原合并预览为 125。保留缓存不等于完全复刻 Photoshop 的文字边缘合成。

2026-10-10 验收：292 项单元测试、类型／应用构建、应用产物校验和仓库边界检查通过。真实富文本文件的最终浏览器报告绑定构建 `b2618f1cc8289222`，完整闭环通过；之前的 `3d-preview-mockup.psd` 和 `bc2.psd` 浏览器回归也通过。最终产物 4,312,481 B raw／1,409,060 B gzip，未超出现有预算。

## 按层诊断与性能（2026-10-10）

导入不再因“存在文字”统一警告。检查 PSD 真实文字描述，给出图层 ID、完整组路径、问题代码及具体属性；不把名称中的 `<TCC_3>` 等标签解释为 PSD 指令。UI 将文字问题放在默认折叠的“文字检查”中，没有问题的文字层不列入警告，保留像素缓存的说明移入普通文件信息。

检查项目包括原抗锯齿方式、关闭／自定义字偶距、分段字距／行距、实际含可断词单词的文字框自动断词、多行排版器、标点悬挂、禁用连字及大写设置。这里只指出当前渲染模型未保留的明确设置，不将其描述成已观察到的像素错误。浏览器以 CSS `local()` 检查文件实际用到的字体，不枚举系统字体、不请求权限、不联网下载；加载成功的字体注册到当前页面供重绘使用。同名字体去重、并发最多 8 项、缓存有界。无法使用 FontFace 或检测超时记为未检测，不伪报缺失。字体不可用时指出字体名称及所属层。页面最多注册 256 个本地字体，已注册字体不因缓存淘汰而从正在编辑的文档中消失。

`image.document.open` 除原有 `warnings` 外返回 `textDiagnostics`，包含 `layerId`、`path`、`fontNames`、`fontCheck` 和 `issues[{code,detail}]`。无浏览器的本地调用无法检测本机字体时会标为 `unavailable`（检测能力不可用）；真正加载失败的字体使用 `issues.code = font-unavailable`。

本机 `rich-text.psd` 的 Arial 字体均可用，因此没有字体缺失提示。文件包含 7 层 sharp 抗锯齿及 1 层 none 抗锯齿，当前浏览器重绘无法保持这些 Photoshop 选项，所以仍有具体说明；`Centered rich text` 另含关闭自动字偶距的区间，4 个文字框同时满足启用自动断词及含可断词单词。这些限制只在修改文字后重新排版时生效，未修改层仍保留原像素缓存。

性能优化：

- 对需要原生档案的复杂 RGB8 PSD，先尝试分块导入，成功后仅解码合并预览，避免“完整解码后失败再分块”的重复工作；保留原有安全校验及失败后的兼容回退。
- PSD 附加块列表只扫描一次并传给后续路径；同一图层的兼容诊断不再按属性重复遍历子树。
- 文字排版复用分词器和样式对象，每次重绘局部缓存相同字体／字距／字形的测量结果。测量缓存不跨重绘，字体加载或样式变化不会沿用旧宽度。

本机实际文件的对照结果（不代表所有 PSD 或 GPU 帧率）：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 热导入中位数，同进程交替测量、去除预热 | 53.11 ms | 42.38 ms |
| 8 层文字重绘中位数 | 10.27 ms | 5.31 ms |
| 8 层文字 measureText 调用数 | 780 | 159 |
| 重绘像素差异 | — | 0 |
