# P2：渲染架构

## 已实现

- 在 Haiyue Engine 的同一 WebGPU 设备上连接 RGB8 区域合成、颜色显示转换、金字塔缩小和视口呈现。合成结果以 straight alpha 保持在 GPU，缩小时按 Alpha 加权，最终带邻接像素的瓦片再转为 premultiplied alpha。避免每个叶瓦片的 GPU→CPU→GPU 往返。
- 显示瓦片和中间金字塔共用 48 MiB 缓存，优先保留较高的缩小级别，同级按 LRU 淘汰，避免冷帧遍历反复生成相邻区域。源图纹理与临时合成表面共用 8 MiB 池。借用的资源直到命令提交前都受保护；同尺寸淘汰可复用纹理。每个参数池最多 64 KiB，命令提交后复用，设备丢失和销毁时释放。
- 同一不可变位图的源纹理跨透明度、混合模式和滤镜设置调整复用；局部像素修改只使受影响的显示瓦片及其上层缩小结果失效。元数据修改沿用 P0 的零绘制路径。
- 可见瓦片全部准备好后一次提交画面。导航器和持久缓存回读随后执行，每批最多 16 个瓦片、4 MiB staging buffer、一次 mapAsync；复用 staging buffer。平移／缩放复用已有导航器位图，新的视口请求取消旧后台任务。
- 持久预览缓存增加 readMany／writeMany，每批最多 16 条，写入总量最多 4 MiB；替换、LRU 淘汰与总字节数在同一 IndexedDB 事务中提交。缓存仍限制 64 MiB，渲染版本和颜色设置参与键，缓存损坏或不可用可重新生成。
- 只在画布大小或配置变化时重建显示目标；GPU 丢失时取消旧任务，通过引擎恢复设备、重建资源并重绘。

## 适用范围

GPU 常驻路径支持 RGB8、九种已实现的混合模式、亮度／对比度／饱和度／黑白／反相及其滤镜不透明度、可表达为矩阵与 TRC 的嵌入 RGB 配置。当前最多八个可见层；蒙版、图层样式、复杂滤镜、CMYK、高位深、显式 ICC 工作流及 HDR 继续使用参考合成与原有 WebGPU 显示路径。原生编辑、导出和工程存储不依赖显示缓存。

首次精确缩小仍需读取覆盖区域的原始像素；本批不声称冷启动任意超大 PSD 都能瞬时完成。无 WebGPU 时保留参考显示。

## 验收

- `test/render-p2.test.mjs`：资源预算、占用保护、淘汰复用、损伤失效、释放后不复活、颜色／图层准入。
- `test/render-p2-browser.mjs`：9001×65 透明 PSD，奇数尺寸、跨瓦片边缘、连续六次透明度调整、缩放复用、持久缓存恢复、损坏缓存重建、设备丢失恢复、批量缓存事务与 64 MiB 淘汰记账。直接采样最终 GPU 目标，与独立 CPU 缩小及双线性采样结果比较；测试采样不计入产品回读。另验证嵌入 Display P3 的矩阵／TRC 转换与 LittleCMS 的结果，以及显式 ICC 设置的参考回退。
- 冷帧提交上限 12 s、连续调整提交上限 1 s、像素通道误差上限 3；热帧要求源上传为零、资源新增为零，所有常驻帧要求呈现前回读为零。另记录测试 GPU 采样完成的等待时间，单独要求小于 1 s；它包含测试自身的像素回读，不等同于纯 GPU 渲染时间。结构指标、CPU 提交和完成等待分别记录，不以平均耗时掩盖回读或资源增长。
- 复跑 `performance-p1-browser.mjs` 的九种混合／五种滤镜／蒙版回退，`tiled-viewport-browser.mjs` 的 20000×12000 文档，及原生高位深／HDR 回归。大图冷帧要求每个叶瓦片最多合成一次，避免缓存淘汰导致隐性重复工作。

先执行 `npm run app:check --workspace imageEditor`，再运行 `node imageEditor/test/render-p2-browser.mjs`；可通过 `CHROME_PATH` 指定 Chrome。产物在 `artifacts/render-p2/`，带构建哈希、源文件指纹、fixture 哈希、runner、revision 和 dirty 状态。这些是本机诊断数据，不是跨机器正式性能认证。

## 本次验证（2026-10-11）

- 474 项 Node 测试、5 组浏览器回归、类型检查、构建／包体和仓库边界全部通过，汇总见 `artifacts/render-p2/acceptance.json`。
- 构建 `d6f19637ba7bf633c559e69a415f4a35ddd5aa18321e145550a50a67f8760413`：raw 4,585,603 B / gzip 1,510,630 B；沿用 4,600,000 B / 1,520,000 B 预算。
- 9001×65 透明样例冷帧提交约 88.8 ms；连续六次透明度调整提交约 1.1–1.4 ms，源上传和纹理新增均为零。测试 GPU 采样完成等待约 40–57 ms，另行记录，不把提交时间等同于用户可见延迟。
- 20000×12000 样例首次精确视口约 5.47 s，不含文件导入；3713 个叶瓦片各合成一次，原始像素上传共 960,000,000 B，没有重复上传。缩放约 108 ms、平移约 125 ms，显示缓存和合成池始终在预算内。
- GPU 常驻帧呈现前回读为零；跨瓦片、Alpha、奇数尺寸和 Display P3 对照的最大通道误差约 2.50（门槛 3）。缓存损坏重建、设备恢复、蒙版参考回退、原生 HDR 浮点值与 P0 零无效工作回归通过。HDR 检查采用模拟环境，不是物理 HDR 认证。
