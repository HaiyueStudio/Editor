# P1：解码、换页与预览性能

## 已实现

- PSD/PSB 通道使用 64 KiB 输入预读。ZIP 仍按 1 KiB 推进解压，避免高压缩率输入一次产生过大的待消费队列；RLE 同样复用预读窗口。
- 合并图 ZIP 只解压一次，再分发各通道。总原始通道数据不超过 8 MiB 时使用内存，超过时将 32 行通道带压缩到磁盘，支持跨通道、不满 32 行的边界及 8/16/32 位预测。
- TIFF LZW 仅在 64 KiB 输入补充和输出提交处等待，保留 early-change 字典、特殊 next-code、截断、输出长度及取消校验。
- PSD、TIFF、EXR 共用原生条带写入器。当前瓦片行最多使用 16 MiB，能容纳的列直接写最终瓦片；其余列继续磁盘暂存，超宽 CMYK 保持有界内存。
- 磁盘页读写每批最多 16 页（4 MiB），批量事务减少 IndexedDB 往返；逐页 SHA-256、工作集租约和写入完成后发布引用的约束不变。
- 大文件 PSD、TIFF/EXR 的文件选择器导入转到 Worker，可通过现有取消按钮终止。预览 Worker 每帧只传一次状态，省去 PSD 档案和智能对象源资产的重复复制；只返回区域像素，结束后释放 Worker 及其页面锁。
- 简单单图层使用最多 4 MiB 的空间预取，把最多 16 个 256 像素叶瓦片合为一次 Worker 请求；无效果、满画布、100% 不透明度的单栅格层直接读取区域像素，避免重复执行混合循环。高位深采用更小预取区域，复杂图层继续保守分块。
- 大图视口先准备可见瓦片，整帧提交；导航器完整缩略图随后可取消地补齐。图层缩略图和对话框预览也走后台计算。
- 新增独立的 64 MiB IndexedDB 预览 LRU 缓存。缓存键基于实际渲染输入、色彩配置及渲染版本；不依赖 revision，避免撤销分支碰撞。缓存不参与工程像素存储，损坏、配额不足、不可用时重新生成。文档磁盘页回收不承担预览缓存的引用保活。
- 在现有 Haiyue Engine 设备上实现 256×256 区域 GPU 合成，支持九种已有 GPU 混合模式，以及亮度、对比度、饱和度、黑白、反相智能滤镜及其不透明度。最多八个相交图层、临时 GPU 内存不超过 8 MiB。CMYK、高位深、蒙版、样式、其他滤镜等仍使用 Worker 中的参考算法及 LittleCMS。
- ICC 两个参考工具的 JavaScript 包装代码纳入既有 Rollup 压缩流程；WASM、许可与功能保持完整，不提高应用包预算。

## 验收与范围

`test/performance-p1.test.mjs` 检查有界 Worker 请求聚合与取消、单层直读的像素一致性、不复制归档资产、单次 ZIP 读取、奇数通道边界、磁盘分发、30000 像素宽 CMYK、无暂存的常用条带、LZW 字典增长、批量事务与损坏页、跨实例预览复用及撤销分支缓存键。

`test/performance-p1-browser.mjs` 使用 9001×257 双图层 PSD，在真实 WebGPU 中对比混合/滤镜输出和 CPU 采样（按视口像素中心做双线性采样），检查蒙版 Worker 回退、渲染取消、IndexedDB 缓存预算及刷新复用。产物记录 fixture SHA-256 和应用 buildHash。另运行原有分块、原生位深、存储回收和 ICC 浏览器场景。

首次以适合窗口方式显示、又没有可用合并预览/持久缓存的文档，精确缩小图仍需读取涵盖的原始像素；本批将其移到后台，并避免在局部视口绘制前额外扫描整个导航器。缓存仅用于显示，导出和编辑仍读取原始像素。GPU 快路径有明确准入条件，不代表全部 Photoshop 效果都已 GPU 化。
